1 The 4-Stage Project Lifecycle

Every phase of this project executes through a rigorous 4-stage engineering lifecycle to eliminate vibe-coding:

Stage Phase Name Key Deliverables & Gatekeeper
Stage 1 PRD & Technical Spec PRD.md / PRD.pdf and TRD.md / TRD.pdf completed and approved.
Stage 2 Sprint Planning 4 Sprints broken into small, numbered User Stories with acceptance criteria.

Stage 4 Code Defense & Verification 2 Socratic interview questions, user explains logic flow in own words, git commit.
2 Story-by-Story Pull Request (PR) Workflow
Step 1: Pre-Flight Concept Briefing Mentorship

Assistant explains the problem, real-world everyday analogies (e.g. state as whiteboard notes), and the exact syntax patterns being introduced.

Step 2: Implementation Plan (/plan) Planning Mode

A structured implementation_plan.md artifact is generated listing specific files, props, and verification steps. Execution pauses until approved.

Step 3: Targeted Implementation Coding

Minimal, clean code diffs with detailed explanatory comments. Zero unrelated file edits. Strict adherence to RULES.md.

Step 4: Automated Verification QA Audit

Run npx tsc --noEmit (0 errors), npm run lint (0 warnings), and visual browser validation across desktop, mobile, and all 4 themes.

Step 5: Socratic Code Defense Interview Prep

Assistant pauses and asks 2 targeted interview questions. Safith explains the flow in his own words before the story is approved.

4 Educational Debugging Protocol
🛠️ When Errors Occur
Never silently patch an error! Walk through the stack trace together:
1. Pinpoint: Which file and line number threw the error?
2. Root Cause: What was JavaScript/TypeScript expecting, and why was it violated?
3. Fix & Learn: Apply the minimal targeted fix and discuss how to prevent similar issues in production.
